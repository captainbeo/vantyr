Base URLs// two protocols, one key

Every Vantyr model works over both protocols with the same sk- key. Pick the URL that matches your client — the difference is only the /v1 suffix.

Anthropic-compatible
for Claude Code · Anthropic SDK
https://vantyr.xyz

No /v1 suffix. Use with x-api-key header or ANTHROPIC_BASE_URL. Requests hit /v1/messages under the hood.

OpenAI-compatible
for Codex CLI · OpenAI SDK · agents
https://vantyr.xyz/v1

With /v1. Serves /v1/chat/completions, /v1/responses, /v1/models. Bearer token auth.

Why two URLs? Anthropic's protocol expects the base to be the server root (it appends /v1/messages itself), while OpenAI tools expect the versioned root. Same key, same models, same billing on both.

Your key: create one in the console at Keys. It is shown once — copy it then. The key works on both URLs.

Setup// three steps, five minutes

01

Create an account and top up

Register at vantyr.xyz (free; a Cloudflare captcha keeps the bots out). Top up your wallet from the Wallet page with USDT or USDC on 8 networks — minimum $1, credit lands in 1–3 minutes after the transaction confirms.

Wallet balance is consumed per token as requests run. Failed requests are refunded automatically — you never pay for a response you didn't get.

02

Create a key and paste the config

Keys page → Add Key. Give it a name, optionally a quota ceiling or model restriction. The full sk-… value appears once — copy it. Then pick your agent below:

Claude Desktop app (recommended): enable Developer Mode (Help → Troubleshooting), then Developer → Configure Third-Party Inference…, set provider to Gateway, and enter base URL https://vantyr.xyz + your key. Claude Code

Vantyr serves the native Anthropic protocol, so Claude works with no code changes. There are two surfaces — the Claude Desktop app (recommended: guided setup with connection test and automatic model discovery) and the Claude Code terminal CLI (environment variables).

1. Enable Developer Mode. In the app menu: Help → Troubleshooting → Enable Developer Mode. The app restarts with a Developer menu.

2. Open the inference configuration. Developer → Configure Third-Party Inference…

3. Enter the gateway credentials. In the Connection section, set Inference provider to Gateway, then in the Gateway credentials card:

Inference provider
Gateway
Gateway base URL
https://vantyr.xyz
Gateway API key
sk-your-vantyr-key
Credential kind
Static API key
Gateway auth scheme
Bearer (default)

4. Apply. The window validates the connection as you type — Vantyr implements GET /v1/models, so your claude-* models are discovered automatically in the model picker. Click Apply Changes and the app relaunches against Vantyr.

While a gateway is active, the Desktop app runs sessions locally (no SSH or Anthropic-hosted environments), and Remote Control is unavailable. Non-Claude-shaped model IDs (like gpt-6-astra) don't appear via auto-discovery — you can still list them manually under inferenceModels in the developer config.

The terminal CLI is configured with environment variables (there is no Developer Mode in the CLI).

Install (Node 18+)
npm install -g @anthropic-ai/claude-code
Global config — ~/.claude/settings.json (applies to every project)
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://vantyr.xyz",
    "ANTHROPIC_AUTH_TOKEN": "sk-your-vantyr-key"
  }
}
…or per-shell environment variables
export ANTHROPIC_BASE_URL="https://vantyr.xyz"      # no /v1
export ANTHROPIC_AUTH_TOKEN="sk-your-vantyr-key"

Run claude in your project directory; check /status in-session to confirm the base URL is active. Pick a model with claude /model claude-sonnet-5.

Use ANTHROPIC_AUTH_TOKEN (Bearer header) — Vantyr accepts Bearer on the Anthropic endpoint too, and the AUTH_TOKEN form maps directly onto it. If you use ANTHROPIC_API_KEY instead, it sends x-api-key, which also works; just don't mix them up in one shell.

Aider

Aider reads the standard OpenAI environment variables, so it needs no config file.

Install (Python 3.9+)
python -m pip install aider-install && aider-install
Point it at Vantyr — macOS / Linux
export OPENAI_API_BASE="https://vantyr.xyz/v1"
export OPENAI_API_KEY="sk-your-vantyr-key"
Windows PowerShell (restart shell after)
setx OPENAI_API_BASE "https://vantyr.xyz/v1"
setx OPENAI_API_KEY "sk-your-vantyr-key"
Run in a repo
aider --model openai/claude-sonnet-5

The openai/ prefix tells Aider to use its OpenAI-compatible client instead of looking the model up in its built-in list. A "model not in metadata" warning is cosmetic — the request still routes through Vantyr.

Kilo Code

Kilo Code can run as a VS Code extension or a standalone CLI, sharing the same provider config. Add Vantyr as a custom provider:

Install
code --install-extension kilocode.kilo-code   # VS Code extension
npm install -g @kilocode/cli                    # or standalone CLI
Provider config (~/.config/kilo/kilo.json, or Settings → Providers → Custom provider in the UI)
{
  "providers": {
    "vantyr": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Vantyr Gateway",
      "options": {
        "baseURL": "https://vantyr.xyz/v1",
        "apiKey": "{env:VANTYR_API_KEY}"
      },
      "models": {
        "claude-sonnet-5": { "name": "Claude Sonnet 5" },
        "gpt-6-astra": { "name": "GPT-6 Astra" },
        "claude-fable-5": { "name": "Claude Fable 5" }
      },
      "defaultModel": "vantyr/claude-sonnet-5"
    }
  }
}
Run
export VANTYR_API_KEY="sk-your-vantyr-key"
kilo
# inside Kilo: /models  →  select vantyr/claude-sonnet-5

The {env:VANTYR_API_KEY} form resolves only from trusted global config — keep the real key out of committed project files.

Payments// crypto top-up

  • USDT / USDC at 1:1 against the dollar, on 8 networks: TRON (TRC20), Solana, Ethereum, BNB Chain, Polygon, Plasma, TON, Aptos.
  • Minimum top-up $1, no maximum. Wallet credit never expires.
  • After clicking Top Up you get an address and exact amount — send exactly that amount. Credit lands automatically on network confirmation (typically 1–3 minutes; TON can take longer).
  • Payment stuck (sent but not credited after 30 minutes)? Note the transaction hash and contact support — every order is recorded and can be reconciled manually.

Troubleshooting// common failures

401 Invalid API key
The key is wrong or mistyped. Keys are shown once at creation — if you lost it, create a new one in the console. Also check the right env var is set for your agent (VANTYR_API_KEY, ANTHROPIC_AUTH_TOKEN, or OPENAI_API_KEY depending on the tool).
404 / Not Found
Almost always the wrong base URL — Anthropic clients need https://vantyr.xyz (no /v1), OpenAI clients need https://vantyr.xyz/v1. Check both cards at the top of this page.
Model not found / no channel available
The model ID doesn't match. Use exact IDs from the Model Overview — e.g. claude-sonnet-5, not claude-sonnet. Also check the model isn't restricted on your key (Keys page → model limits).
Insufficient quota / balance
Wallet empty or the key hit its quota ceiling. Top up at the Wallet page, or raise/remove the key's quota limit.
Stream disconnected mid-response
Rare upstream hiccup. Your key was not charged for the failed portion (failed requests auto-refund). Retry the turn; if it repeats, check the status banner or ask in the Discord community.

FAQ//

Where do I see my usage and spend?

Usage page in the console: every request with model, tokens, and amount billed. Wallet page: balance and top-up history.

Which model should I pick?

claude-sonnet-5 for most coding and chat (best quality per dollar); claude-fable-5 when the task is genuinely hard; gpt-5-6-luna or gpt-6-sol when volume beats peak quality.

Do you support streaming / tools / structured output?

Yes — all standard client features pass through on every model: SSE streaming, tool calling, structured outputs, prompt caching.

Is my data used for training?

Vantyr is a relay: prompts and completions are forwarded to the upstream provider and logged only as billing metadata (token counts, model, timestamp) — never message content.

Can I use one key across many tools?

Yes — the same key works on both base URLs in any number of clients. For separating budgets, create one key per tool and set a quota ceiling on each.
