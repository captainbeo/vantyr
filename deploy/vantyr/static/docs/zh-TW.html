基底 URL// 兩種協定，一把金鑰

每個 Vantyr 模型在兩種協定下都使用同一把 sk- 金鑰。請選擇符合您用戶端的 URL——兩者差別只在 /v1 後綴。

Anthropic 相容
適用於 Claude Code · Anthropic SDK
https://vantyr.xyz

無 /v1 後綴。搭配 x-api-key 標頭或 ANTHROPIC_BASE_URL。實際上，請求會送到 /v1/messages （在底層）。

OpenAI 相容
適用於 Codex CLI · OpenAI SDK · 各類 Agent
https://vantyr.xyz/v1

帶有 /v1。提供 /v1/chat/completions, /v1/responses, /v1/models。採 Bearer 權杖驗證。

為什麼有兩個 URL？ Anthropic 的協定預期基底 URL 是伺服器根路徑（它會自行附加 /v1/messages 本身），而 OpenAI 工具預期的是帶版本號的根路徑。兩個 URL 之下都是同一把金鑰、同樣的模型、同樣的計費。

您的金鑰：請在控制台的 金鑰。金鑰只會顯示一次——屆時請立即複製。這把金鑰在兩個 URL 上都有效。

Agent 指南// 每個工具的精確設定

每個區塊都有複製按鈕。請將 sk-your-vantyr-key 換成您真正的金鑰。所有設定中的模型 ID 都可從 模型總覽 自行挑選——範例使用 claude-sonnet-5 （高性價比之選）與 gpt-6-astra.

Claude Code

Vantyr 提供原生的 Anthropic 協定，因此 Claude 無需改動任何程式碼即可使用。有兩種使用方式—— Claude Desktop 應用程式 （建議：有引導式設定、連線測試與自動模型探索）以及 Claude Code 終端機 CLI （環境變數）。

1. 啟用開發者模式。 在應用程式選單中： Help → Troubleshooting → Enable Developer Mode。應用程式會帶著 Developer 選單重新啟動。

2. 開啟推論設定。 Developer → Configure Third-Party Inference…

3. 輸入閘道憑證。 在 Connection 區段中，將 Inference provider 設為 Gateway，然後在 Gateway credentials 卡片中：

Inference provider
Gateway
Gateway base URL
https://vantyr.xyz
Gateway API key
sk-your-vantyr-key
Credential kind
Static API key
Gateway auth scheme
Bearer (default)

4. 套用。 視窗會在您輸入時即時驗證連線——Vantyr 實作了 GET /v1/models，因此您的 claude-* 模型會 被自動探索 進到模型選擇器中。點擊 Apply Changes 後，應用程式會以 Vantyr 重新啟動。

當閘道啟用時，Desktop 應用程式會在本機執行工作階段（不使用 SSH 或 Anthropic 託管環境），且 Remote Control 無法使用。非 Claude 形式的模型 ID（如 gpt-6-astra）不會經由自動探索出現——您仍可在開發者設定的 inferenceModels 中手動列出。

終端機 CLI 是用環境變數設定的（CLI 中沒有開發者模式）。

安裝（需要 Node 18+）
npm install -g @anthropic-ai/claude-code
全域設定 — ~/.claude/settings.json（套用到所有專案）
{
  "env": {
    "ANTHROPIC_BASE_URL": "https://vantyr.xyz",
    "ANTHROPIC_AUTH_TOKEN": "sk-your-vantyr-key"
  }
}
…或每個 shell 的環境變數
export ANTHROPIC_BASE_URL="https://vantyr.xyz"      # no /v1
export ANTHROPIC_AUTH_TOKEN="sk-your-vantyr-key"

執行 claude 於您的專案目錄中；在內部輸入 /status 以確認基底 URL 已生效。用 claude /model claude-sonnet-5.

使用 ANTHROPIC_AUTH_TOKEN （Bearer 標頭）——Vantyr 在 Anthropic 端點上也接受 Bearer，而 AUTH_TOKEN 這種形式可直接對應上去。如果您改用 ANTHROPIC_API_KEY 的話，它會送出 x-api-key，這同樣有效；只是別在同一個 shell 中混用兩者。

Codex CLI

OpenAI 的終端機 Agent。Codex 使用 Responses 協定 API，並在其設定檔中需要一個 provider 項目。

安裝
npm install -g @openai/codex
~/.codex/config.toml — 新增 Vantyr provider
model_provider = "vantyr"
model = "claude-fable-5"
review_model = "claude-sonnet-5"
model_reasoning_effort = "high"
disable_response_storage = true

[model_providers.vantyr]
name = "OpenAI"
base_url = "https://vantyr.xyz/v1"
wire_api = "responses"
env_key = "VANTYR_API_KEY"
supports_websockets = false
supports_standalone_web_search = false
request_max_retries = 1
stream_max_retries = 1
把金鑰放進環境變數
export VANTYR_API_KEY="sk-your-vantyr-key"   # macOS/Linux
[Environment]::SetEnvironmentVariable('VANTYR_API_KEY','sk-your-vantyr-key','User')   # Windows

請保持 name = "OpenAI" 原樣不變——Codex 的遠端壓縮依賴這個顯示名稱來運作。provider ID（vantyr）才是您的 model_provider 所選擇的對象。如果您同時用 OpenAI 帳號使用 Codex，兩份設定可以共存——provider 區塊只會路由 Vantyr 的流量。

Aider

Aider 會讀取標準的 OpenAI 環境變數，因此不需要設定檔。

安裝（需要 Python 3.9+）
python -m pip install aider-install && aider-install
將它指向 Vantyr — macOS / Linux
export OPENAI_API_BASE="https://vantyr.xyz/v1"
export OPENAI_API_KEY="sk-your-vantyr-key"
Windows PowerShell（之後請重新啟動 shell）
setx OPENAI_API_BASE "https://vantyr.xyz/v1"
setx OPENAI_API_KEY "sk-your-vantyr-key"
在 repo 中執行
aider --model openai/claude-sonnet-5

前綴 openai/ 會讓 Aider 使用其 OpenAI 相容用戶端，而不是在內建清單中查找該模型。「model not in metadata」警告只是表面問題——請求仍會經由 Vantyr 路由。

Kilo Code

Kilo Code 可以作為 VS Code 擴充功能或獨立 CLI 執行，兩者共用同一份供應商設定。請將 Vantyr 新增為自訂供應商：

安裝
code --install-extension kilocode.kilo-code   # VS Code extension
npm install -g @kilocode/cli                    # or standalone CLI
供應商設定（~/.config/kilo/kilo.json，或在 UI 中 Settings → Providers → Custom provider）
{
  "providers": {
    "vantyr": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Vantyr Gateway",
      "options": {
        "baseURL": "https://vantyr.xyz/v1",
        "apiKey": "{env:VANTYR_API_KEY}"
      },
      "models": {
        "claude-sonnet-5": { "name": "Claude Sonnet 5" },
        "gpt-6-astra": { "name": "GPT-6 Astra" },
        "claude-fable-5": { "name": "Claude Fable 5" }
      },
      "defaultModel": "vantyr/claude-sonnet-5"
    }
  }
}
執行
export VANTYR_API_KEY="sk-your-vantyr-key"
kilo
# inside Kilo: /models  →  select vantyr/claude-sonnet-5

前綴 {env:VANTYR_API_KEY} 形式只會從受信任的全域設定解析——請勿把真正的金鑰放進已提交的專案檔案中。

疑難排解// 常見問題

401 Invalid API key
金鑰錯誤或打錯字。金鑰只在建立時顯示一次——如果弄丟了，請在控制台建立新的。也請確認您為 Agent 設對了環境變數（例如VANTYR_API_KEY, ANTHROPIC_AUTH_TOKEN，或 OPENAI_API_KEY 等，視工具而定）。
404 / Not Found
幾乎都是基底 URL 用錯——Anthropic 用戶端需要 https://vantyr.xyz （不含 /v1），OpenAI 用戶端則需要 https://vantyr.xyz/v1。請對照本頁 頁首.
Model not found / no channel available
模型 ID 不符。請使用 模型總覽 上的確切 ID——例如 claude-sonnet-5，而不是 claude-sonnet。也請確認該模型未在您的金鑰上受限（金鑰頁面 → 模型限制）。
Insufficient quota / balance
錢包空了，或該金鑰已達額度上限。請到錢包頁面儲值，或調高／移除金鑰的額度限制。
Stream disconnected mid-response
罕見的上游暫時性問題。失敗的部分不會向您的金鑰收費（失敗請求自動退款）。請重試該輪；若再次發生，請查看 狀態橫幅 或到 Discord 社群.

FAQ//

我在哪裡查看用量與支出？

控制台的用量頁面：每筆請求的模型、Token 數與計費金額。錢包頁面：餘額與儲值歷史。

我該選哪個模型？

claude-sonnet-5 應付大多數 coding 與對話（每美元品質最佳）； claude-fable-5 處理真正困難的任務； gpt-5-6-luna 或 gpt-6-sol 在數量比極致品質更重要時使用。

你們支援串流 / 工具呼叫 / 結構化輸出嗎？

支援——所有標準用戶端功能都會在每個模型上透傳：SSE 串流、工具呼叫、結構化輸出、提示詞快取。

我的資料會被用於訓練嗎？

一把金鑰能跨多個工具使用嗎？
